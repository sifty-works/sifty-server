# The layer rules of the repository, checked by scripts/layers.sh (make check) against go list and the source files.
#   A mechanism (db, runner, models, fetch, config, server, apperr, text) imports no module, and runner never imports models.
#   A module is one task of the user; it imports mechanisms and packages of its own module, never another module.
#   A worker is one way of doing a job behind an interface of its module; it imports no other worker.
#   cmd/sifty only wires: it may import anything and runs no SQL.
#   SQL calls and database/sql are for the packages listed after sql and for files named repo*.go or store*.go.
# One line per kind: "mechanism:", "module <name>:", "worker:", "sql:", "wiring:", "outside:" and their packages.
# The packages of a module are those of today that go into the package of that name; upkeep (the daily retention run and the
# model-call journal cleanup, now in cmd/sifty) has none yet and application has only the Shortlist check so far (locate, web search, form reading and answers are not written).
# A deviation of today's code is one line "<package> -> <import or database/sql>" or "<file> -> sql" with "# until: <change>",
# the change that removes it; a line nothing uses any more is reported; remove it. New lines need the owner's decision.
