# Changelog

Notable changes of Sifty, newest first. Versions follow `MAJOR.MINOR.PATCH`.

## Unreleased

- Settings › Monitor › Background work, through `GET /api/work`, names the provider and model that serve a running job that uses a model; waiting counts are computed by one grouped query instead of reading every queued job.
## 0.2.0

- At start, API keys the application holds are scrubbed from the lines already in `logs/sifty.log` and `logs/sifty.log.1`, written before keys were masked; a file with no key is not rewritten. Keys no longer held, such as the key of a removed provider, stay in old lines.
- The recovery notice under the header shows the server's sentence for each recovered file instead of one fixed sentence (web client 0.27.0).
- The notice of a file recovered at start says what happened, in a sentence the status sends as `text` in place of `err` and `broken`: the settings file moved to `.broken-<time>` with the reason and the backup or the defaults used, unknown settings ignored, the site descriptions file moved with the host at fault and the built-in descriptions used. A refused settings file that cannot be moved aside is left as it is instead of being overwritten.
- Removed the one-time import from the previous application.
- A list that cannot be loaded shows an error, not an empty list: the Inbox shows the server's sentence, and Saved answers and the excluded words of a profile say that they could not be loaded (web client 0.26.0).
- Every API key the application holds is replaced by `***` before a line is written to the log file or to the terminal, wherever in the line it stands; before, keys were hidden only when Settings › Monitor › Logs read the file.
- On a profile whose data, or My data, cannot be read, a decision and a permanent deletion are refused before anything is written, and the list and the vacancy page fail instead of showing Fits you as though the profile had no inputs. Before, the decision or the deletion was saved and the answer was still an error.
- Settings › Monitor has a Logs section: the jobs that failed in the last seven days, moved there from Background work, and the latest warnings and errors of the log, with a Refresh button (web client 0.25.0).
- `GET /api/logs` lists the jobs that failed in the last seven days and the last 200 warnings and errors of the log, newest first, with every held API key shown as `***`. The log file is now written as JSON lines, and the number in "see log #N" starts from the start time, so it does not repeat after a restart. The frontend budget rises to 6,200 lines for the Logs page.
- Settings has a Monitor group. Its Background work page shows what runs, what waits and why, and what failed in the last seven days, each with its reason in a sentence (web client 0.24.0).
- `GET /api/work` lists what background work is running, what waits and why (paused, the daily limit, a held provider, a paid provider not allowed, a retry time), and what failed in the last seven days, each with a sentence instead of the Go error, which goes to the log under the job's id. The sentence is made when a job fails, so failures recorded before this version keep their old text until they age out of the seven days. A document analysis whose provider does not answer now says so.
- `sifty backup [--data-dir <folder>] [--out <file>]` writes the database, the settings file, `vocab/sites.yaml` and the documents and photo into one `.tar.gz` archive, while the application runs and without changing the database; it leaves out the secrets file, earlier database copies and logs, and refuses to overwrite an existing file.
- The SQL of My data, profiles, documents, suggestions and Questions & Answers now lives in one repository file of the `candidate` package, and the handlers and services call it; nothing the user sees and nothing in the interface description changes.
- The list, the vacancy page and decisions no longer wait for a collection, a reading or a recompute that is writing: the database keeps four connections instead of one, and a write waits only for another write. A recompute of Fits you after one changed role stops once the changed results are written, where before it read the whole catalogue again.
- The unused Word document reader and the unused `shortlistcheck.Version` are removed; a `.docx` upload is still refused as before. 170 lines removed.
- A profile whose stored data cannot be read no longer shows an empty list: the list answers "Internal error, see log #id" with a log entry. Queuing readings for decided vacancies still queues them for every profile it can read, and then the job fails with the id of each profile it could not read, instead of quietly queuing fewer.

## 0.1.0

- A background model call that fails because of the request itself — a prompt longer than the provider's context, a command-line answer that is not valid JSON or is over the output limit, an answer in which the model tried to call a tool — now fails only that piece of work and no longer marks the provider as not answering; a prompt too long for the provider fails that reading, check or analysis for good with a sentence, where before it held all background work; three such failures in a row hold the provider like one that does not answer, and any success resets the count. When a provider itself does not answer, background work waits five minutes and then tries the provider again by itself, where before it waited until a call of the user or Check succeeded. A call cancelled in flight is recorded and counts against the daily limit, a failed record is logged, and background work waits when the pause switch or today's calls cannot be read, instead of going ahead.
- `make release` builds the application into its own folder, waits until no collection is running, switches the running application to the new build and checks that it answers with the new version, or else switches back and restores the database copy the new build made; then it moves these entries under the new version, tags and pushes it. `make rollback` returns to the previous build and, when that release changed the database layout, restores the copy made before it and says which one. Both read the data folder, the folder of builds and the checkout from an untracked `release.local`.
- Web client 0.23.0: Undo beside a decision taken in this session returns the role to the stage it came from, where before the button did nothing; the Settings screen draws one page shell when the server is not running, instead of a second navigation rail inside the first.
- The Money tile picks its mark after rounding, so a sum just under the next unit is no longer written with the lower one: 999,950 reads "$1M" instead of "$1000k", and 999.5 reads "1k" instead of "1000".
- Web client 0.22.0: the Inbox asks the server for 100 roles at a time and carries "Show more roles" under the list, while the stage counts, the Sources counts and the "Showing N / M roles" line read the whole selection; the Filters panel has no Industries group, a list row and the vacancy page carry no industries, and a profile has no target industries.
- Industries are gone from the application: the Inbox has no Industries filter and no industry counts, a list row and the vacancy page carry no industries, a profile has no target industries and no longer narrows its Inbox by them, `GET /api/industries` is no longer served, and collection no longer derives industries from board tags or from a site's description. A profile that still holds target industries keeps them stored and ignores them. A migration drops the stored industries of every vacancy; vacancies and decisions are kept.
- Saving My data or a profile now stores every field the save names, whatever its value: a list left empty in the editor and sent as "none" is cleared exactly as an empty list is, where before it kept its old entries; a field the save does not name keeps its stored value, and an empty profile name is still ignored. The interface description is unchanged.
- The role list arrives in windows: `GET /api/vacancies` takes `limit`, a whole number from 1 to 200 (100 when left out), and `offset`, a whole number from 0, and returns that part of the chosen order, so a profile with 1,500 roles sends 100 on the first request. A `limit` or an `offset` that is not a whole number in range is refused with a sentence. The answer gains `matching`, the number of roles the filters select, counted whole; `total`, the stage counts, the Sources counts and the empty text are still counted over the whole selection, and an `offset` past the end gives no rows with the counts unchanged.
- A refused setting is told in a sentence about the setting, with no key path or quoting: an unknown provider type, a provider cost, a provider chosen for a kind of model work that is not in the list, a weight, a rate, the port, the interval and a timeout. The age limit is checked by one rule for the Sources screen and for the settings file: a whole number from 1 to 1200, or absent for no limit. A settings file that holds anything else, including an explicit 0 written by hand, is put aside as `sifty.yaml.broken-<time>`, the server starts on the newest valid backup or on the defaults, and the recovered notice shows the same sentence.
- Web client 0.21.0: the Inbox filter reads "Published — All, 7 days, 30 days" in place of "Collected", Newest follows the role's own publication date, and Sources carries the field "Do not collect roles published more than N months ago" beside the collection schedule, which keeps its value when automatic collection is switched on or off.
- Sources carries an age limit, "Do not collect roles published more than N months ago": a whole number of months, empty for no limit. A posting whose listing gives an older publication date is not collected and its page is not requested; a posting with no publication date is always collected. The limit removes nothing already collected, so raising or clearing it brings older roles back the next time a source shows them.
- The Inbox filter "Collected 7 / 30 days" is replaced by "Published — All, 7 days, 30 days", which reads the role's own publication date instead of the day it entered the catalogue; a role with no publication date passes every choice. Newest now sorts by publication date alone, newest first, with undated roles last.
- Web client 0.19.0: the Files tab shows, beside the documents, the facts an analysis proposes — each with its field, its value, the quote behind it and the document it came from — and takes them into My data with Accept or drops them with Reject; a proposal that contradicts a fact already held shows both values and asks which one stands, and the tab button carries the count still to review. The link row of fetched pages now appears only while Contacts and links is being edited.
- Web client 0.18.0: the Files tab of the profile lists documents added as files, as pasted text or as links, each card reading its own state and offering Analyze, Cancel analysis, Retry analysis, its text, its original, "Use as evidence" and delete; fetched pages stand inside Contacts and links with "+ Add link" and "Refresh source", and the tab is laid out in two columns, the right one held for the suggestions still to come.
- Web client 0.17.0: the first role of the list opens by itself, so the working area no longer stands empty with roles in the list; an empty list reads "No roles".
- Web client 0.16.0: when the open role leaves the list — moved to another stage, deleted, or hidden by blocking its company — the next role opens instead of an empty working area.
- Web client 0.15.0: hovering a shortened Location tile in the Fits you band shows the full list of places.
- The Location tile of the Fits you band uses the same short form as a list row, "AD · AE +195 more", instead of listing every place; the full text comes with it for hover, and the verdict and the score are unchanged.
- Web client 0.14.0: hovering a shortened location in a list row shows the full list of places.

- Links become documents: "+ Add link" takes an address and makes a document from the text of the page behind it, read at the address as you typed it, with no model call; the same page added again in another spelling (tracking parameters, `www.`, a trailing slash) returns the document you already have, and two adds at the same moment give one document; a private address, a page behind a login or refusing automatic reading, a page that is not found or not loaded, one that is not a web page and one without text each say so and make no document; "Refresh source" reads the page again, writes nothing when its text is unchanged, and when it changed replaces the text so that the next Analyze starts from the beginning of the new text; pasted text and md or txt files say they have no source to read again.
- Suggestions from a document can be answered: Accept writes the fact where it belongs — a skill into My data at level Proficient, a language and a work role into My data, a target role into the active profile — and Reject writes nothing; a suggestion that names a language at a level other than the one held carries the current value beside the proposed one, so keeping the current value is a Reject and using the proposed one is an Accept; a fact already answered is not offered again by a later analysis of the same document, and a fact the profile already holds is not offered at all.
- A document whose analysis was running when the server stopped is set back to "ready" at the next start, with the reason that the analysis was interrupted, and the chunks already read are kept, so Analyze continues from the chunk reached.
- Applicant tracking boards are one module each, with the hosts they own and the shape of a vacancy address on them; a vacancy on a European Greenhouse or European Lever board is now recognised as a board vacancy, so the same vacancy from two sources is matched as one and a company exclusion matches its apply address.
- Documents: a CV or a note arrives as a file (pdf, md or txt, at most 2 MiB) or as pasted text, keeps its extracted text and its original, is listed newest first, can be marked "Use as evidence" and can be deleted with its file; the text of a pdf is read by the `pdftotext` program of poppler when it is installed, and a pdf stored before that is read again by `POST /api/documents/{id}/refresh`; when the program is missing the document says how to install it, and nothing is analysed by a model.
